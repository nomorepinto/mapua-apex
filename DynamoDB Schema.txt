Reorganized schema

ORGANIZATION
PK: ORGANIZATION#uuid
SK: ORGANIZATION#uuid
name: string
is_higher_council: boolean (default false)
signatories: [
  { role: "adviser", signatory_id: "adv001" },
  { role: "dean",     signatory_id: "dean001" }
]
Desk directory for this org (one person per role).
Allowed desk roles: adviser | dean | osaar | cdm | admin.
Stored in that role order even if the write sent a different order.
Not stored on SIGNATORY. Approval routing uses org desks for adviser
and dean. If is_higher_council is true, Dean is skipped; Adviser still
reviews first.
OSAAR and CDM are campus-wide: OSAAR_SIGNATORY_ID and
CDM_SIGNATORY_ID in the API env (plain uuid or SIGNATORY#uuid).
Rename those people in place (PUT /signatories on the same id).
admin may occupy a desk but is not in the approval sequence.
DELETE /admins/organizations/{id} is guarded: it removes the ORGANIZATION item
only when the org owns no EVENT/SUBMISSION rows (GSI1PK = ORGANIZATION#id) and
no COLLABORATION POINTER rows (PK = ORGANIZATION#id, SK begins COLLAB#);
otherwise it returns 409 and leaves the item untouched. Delete does not rewrite
student Cognito custom:organization_id.

EVENT
PK: EVENT#uuid
SK: EVENT#uuid
sent_at: timestamp
GSI1PK: ORGANIZATION#uuid
GSI1SK: timestamp

Org event list queries GSI1 (first 25 EVENT items), then each event's
SUBMISSION# children. Student GET /organization reads this
ORGANIZATION item directly.

Deny sets status
"denied", drops GSI2, and the student cannot edit. GSI2 is also dropped
on the last approve (status stays "approved" / "denied", current_signatory
is left as the last desk).
"finished" is a terminal, post-approval status set only when the event's
post-evaluation is completed via the arcus-evaluation system; like "approved"
and "denied" it is not editable. There is no "ongoing" status — an event
starting is recorded in the activity log only (deferred until logging ships).
On the last approve the backend also writes an "event scheduled" NOTIFICATION
(system-created, not client-postable) that surfaces in the org_submitter
Timeline Reminders and triggers an SES email with the arcus attendance and
evaluation links.
The arcus apps reach the backend over server-to-server endpoints (shared secret
ARCUS_SERVICE_TOKEN, not a Cognito JWT): GET /api/v1/arcus/events lists
approved/finished submissions whose stateless visibility window is open (derived
per request from activity_details.date_of_event in Asia/Manila — attendance opens
at the start of the event day, evaluation stays open
ARCUS_POST_EVALUATION_WINDOW_DAYS days after), and
POST /api/v1/arcus/events/{event}/submissions/{submission}/finish transitions
approved -> finished (writing finished_at) only inside that evaluation window.

SUBMISSION
PK: EVENT#uuid
SK: SUBMISSION#uuid
submission_type: string
sent_at: timestamp
status: "pending" | "approved" | "denied" | "returned" | "finished"
current_signatory: SIGNATORY#uuid
signatory_sequence: [ SIGNATORY#uuid ]   (ordered routing snapshot, written at submit time; the ONLY stored form of the chain — signatory_chain is derived at read time, never persisted)
collaboration: {
  dependent_organization_ids: [ ORGANIZATION#uuid ]   (index-only collaboration dependents; empty/absent = no collaboration)
}
GSI1PK: ORGANIZATION#uuid
GSI1SK: SUBMISSION#uuid
GSI2PK: SIGNATORY#uuid   (sparse: present while pending or returned on a desk)
GSI2SK: timestamp
finished_at: timestamp   (sparse: stamped when status becomes "finished" via the arcus-evaluation finish endpoint)

activity_classification: {
  activity_type: "co-curricular" | "extra-curricular"
  total_org_members: number
  nature: "major" | "minor"   (OSAAR-set via the signatory classification PATCH; not part of the student create body)
}
proponents: [{
  id, position_title, first_name, middle_name, last_name, suffix,
  student_number, program_and_year, date_of_submission, department,
  position_of_applicant, org_or_course_section, contact_number,
  email_address, facebook_link
}]
activity_details: {
  title_and_nature, description, objectives, venue,
  date_of_event, day_of_event, time_of_event,
  expected_participants, individual_contribution, proposed_budget
}
time_of_event is 24-hour "HH:MM - HH:MM" (start and end).
The form lists hours 1–12 and minutes in 5-minute steps. Saved times must fall between 7:00 AM and 9:00 PM. End is not earlier than start, and start and end cannot be the same.
institutional_alignment: {
  mission_statements: { competitive, research, solutions }
  core_values_explanation, peo_explanation, sdg_explanation
}
detailed_budget_proposal: {
  items: [{ item_no, unit, quantity, price_per_unit, total }]
  grand_total
}
venue_reservation: {
  has_reservation: boolean
  equipment_requested: { items: [{ name, purpose, remark }] }
  function_rooms: { items: [{ date_needed, end_date_needed, time_needed, end_time_needed, room_needed, classroom_name, remarks }] }
  audiovisual_equipment: { items: [{ date_needed, end_date_needed, time_needed, end_time_needed, equipment_needed, remarks }] }
}
room_needed is either a fixed room of the venue campus or "Classroom".
classroom_name is only sent on a "Classroom" row and holds that campus's room
code: Makati is "MPO" + 3 digits (MPO101), Intramuros is a direction
(N, W, S, E, NW, NE, SW, SE) + 3 digits (N101, SW204). The room list follows
activity_details.venue, which the student form offers as "Makati Campus" or
"Intramuros Campus" only; the API stores venue as sent.
GSI1 on SUBMISSION is written on create/update (org + submission id).
Admin GET /admins/submissions lists organizations, then queries GSI1 for each
one with GSI1SK beginning SUBMISSION#. Event rows on the same partition are
not included. organization_id is that GSI1PK without the prefix.
organization_name is the name on that ORGANIZATION item.
The student org list still walks EVENT GSI1, then queries each event
partition. GSI2 is the signatory inbox. It stays on return (status
"returned") so the same desk and the student both still see the paper.
The student may edit a returned paper; PUT sets status back to "pending"
and keeps current_signatory / GSI2 on that desk. Deny sets status
"denied", drops GSI2, and the student cannot edit. GSI2 is also dropped
on the last approve (status stays "approved" / "denied", current_signatory
is left as the last desk).

COLLABORATION POINTER (index-only, one per dependent organization)
PK: ORGANIZATION#uuid   (the dependent org, not the proponent)
SK: COLLAB#EVENT#uuid#SUBMISSION#uuid
event_id: EVENT#uuid
submission_id: SUBMISSION#uuid
sent_at: timestamp
The master SUBMISSION item stays the single source of truth. This pointer only
makes the proponent's submission discoverable in a dependent's dashboard: the
student org list queries the base table on PK = ORGANIZATION#<dep> with SK
beginning COLLAB# (no GSI is needed — DynamoDB cannot index the N values of an
array), then resolves each pointer against the master SUBMISSION. The pointer
carries NO form content. WriteSubmission maintains them: create puts one per
dependent, update diffs the dependent set against the stored collaboration
(adds new, deletes removed). A dependent reads the shared submission and its
NOTIFICATION timeline through SubmissionAccess (requireProponent false) but
cannot edit or resubmit — only the proponent (the event's GSI1PK org) may PUT.
role on the API response is "dependent" for these rows, "proponent" otherwise.

NOTIFICATION
PK: SUBMISSION#uuid
SK: NOTIFICATION#timestamp
signatory: SIGNATORY#uuid
notif_type: "approved" | "fully approved" | "denied" | "returned" | "event scheduled"
comment: string (mandatory if denied or returned)

Students GET / POST / PUT the timeline for their org's paper.
Signatories POST a row on an open desk (does not change submission status)
and PUT a row they authored. POST writes SK = now (UTC, second precision).
PUT replaces notif_type / comment in place; SK does not change.
Students may also change signatory on PUT. Signatory PUT keeps the author.
Approve / return / deny still insert a NOTIFICATION row as a side effect.

SIGNATORY
PK: SIGNATORY#uuid
SK: SIGNATORY#uuid
name: string
role: "adviser" | "cdm" | "dean" | "osaar" | "admin"
department: string (deans only, e.g. SOIT)
GSI4PK: ROLE#ADVISER | ROLE#CDM | ROLE#DEAN | ROLE#DEAN#{DEPARTMENT} | ROLE#OSAAR | ROLE#ADMIN
GSI4SK: SIGNATORY#uuid

A SIGNATORY item is the person. It has no organization_id.
GET /signatories/me and admin list/show read this item.
Who occupies a desk for an org is ORGANIZATION.signatories.
GSI4 is the role index, not an org assignment. ROLE#{ROLE} for adviser, cdm, osaar, admin.
Deans may add a department suffix: ROLE#DEAN#SOIT.

Other items copy the signatory id; they do not join back to SIGNATORY:
  ORGANIZATION.signatories[].signatory_id
  SUBMISSION.current_signatory and GSI2PK (inbox)
  NOTIFICATION.signatory (timeline snapshot)
DELETE /admins/signatories/{id} is guarded: it removes the item only when the
person occupies no ORGANIZATION.signatories desk and has no in-flight GSI2
inbox item; otherwise it returns 409 (leaving the item untouched). Delete does
not rewrite the copies above, so prefer replacing a person in place by keeping
the same uuid (PUT name / role / department). A new uuid leaves in-flight
papers, org desks, and Cognito custom:signatory_id pointing at the old id.

ANNOUNCEMENT
PK: ANNOUNCEMENT
SK: timestamp
content: string

All announcements share one partition. List is Query PK = ANNOUNCEMENT
(newest SK first). Show / PUT / DELETE use GetItem / PutItem / DeleteItem
on that PK + SK. SK is the identity (`sent_at` in the API). POST writes
SK = now (UTC, second precision). PUT replaces content in place; it does
not change SK. Admin Cognito group only.

Routing is snapshotted onto SUBMISSION at write time. On create (and on a
student PUT that re-routes), the resolver builds an ordered signatory_sequence
of SIGNATORY#uuid ids and stores it on the item. The sequence starts at
Adviser, then Dean when activity_type is co-curricular, then OSAAR, then CDM
when has_reservation is true. If the submitting organization's
is_higher_council is true, Dean is skipped (even for co-curricular);
Adviser still reviews first, then OSAAR, then CDM when there is a
reservation. Adviser and Dean come from ORGANIZATION.signatories. OSAAR and
CDM come from OSAAR_SIGNATORY_ID and CDM_SIGNATORY_ID. admin is a valid desk
role but is not in this sequence. current_signatory / GSI2PK hold whoever has
the paper now; on a fresh submit current_signatory is signatory_sequence[0].
On approve, ApproveSubmission reads the stored signatory_sequence, finds the
current desk, and advances current_signatory / GSI2 to the next id (or drops
GSI2 when the sequence is done) — it no longer re-reads the org desks or
campus env ids. Items written before this field existed have no
signatory_sequence; the first approve lazily resolves it (via the org desks
and campus env ids) and persists it on the same write.
Return keeps the paper on the current desk (status "returned"). A student PUT
on a returned paper keeps that desk only if it is still in the recomputed
sequence; otherwise routing restarts at signatory_sequence[0]. Deny
removes it from the queue (status "denied") and cannot be edited.

When a submission has collaboration dependents, the adviser/dean stage expands
across every organization. The chain is built over [proponent, ...dependents]
in submitted order: first the Adviser of each organization, then the Dean of
each organization (a Dean step for an org exists only when
activity_classification.activity_type is co-curricular AND that org's
is_higher_council is not true), then the campus desks (OSAAR, then CDM when
venue_reservation.has_reservation is true). Signatory ids are de-duplicated
across the whole chain preserving first occurrence, so a person who is adviser
and dean (same or across orgs) signs once. Missing adviser / required dean /
unconfigured campus desk throws UnresolvableSignatoryRoute (422). The rest of
the walk (ApproveSubmission, GSI2 inbox, deny/return) is unchanged — a longer
stored sequence simply means more desks. On a returned re-edit only the
proponent edits and resubmits; the sequence is recomputed, and if the desk the
paper was returned to is no longer in the new chain, routing restarts at
signatory_sequence[0].

signatory_sequence stores bare SIGNATORY#uuid ids in order, which is enough to
route approvals but not to label each hop for a collaboration (two orgs can both
contribute an "adviser"). Detail reads therefore project the stored sequence
into a derived signatory_chain: an ordered array of
{ signatory_id, role, organization_id, organization_name }. SignatoryChainResolver
walks [proponent, ...dependents] org desks to map each id to the role and
organization whose desk it is (first desk wins on a de-duplicated shared
signatory); the campus desks (OSAAR, CDM, matched against the env ids) resolve
to a null organization. signatory_chain is computed on read for the single-record
GET endpoints (student / signatory / admin detail) and is NOT written to the item
and NOT returned by list endpoints — the persisted source of truth stays
signatory_sequence plus the ORGANIZATION.signatories desks.

Deprecated / removed objects

DEADLINE REMINDER (removed)
Was: PK = EVENT#uuid, SK = DEADLINE#uuid, sent_at, deadline.
Reason: orphaned read path with no producer. DynamoKeys::deadline() is defined
but never called, and no route, controller, or writer ever creates a DEADLINE
item. The only read is GET /students/deadlines (ListOrgDeadlines), which walks
each event partition for SK begins_with DEADLINE#. DEADLINE items exist solely
in test fixtures (DeadlineControllerTest) and screenshot mocks
(capture-screenshots.mjs), and delete_events.py only removes them. The object
is therefore deprecated and no longer part of the modeled schema; the dangling
read endpoint still exists in code but returns nothing in production.

SESSION LOG (implemented — session monitoring)
Table: MAPUA_APEX_TABLE (single-table, no separate log table)
Written by: App\Logging\SessionLogWriter
Read by:    App\Logging\LogTableItems::querySessions(), getSessionItem()

Key structure (plan §2.1):
  PK:     SESSION#{session_id}
  SK:     METADATA
  GSI1PK: LOG#SESSION#{YYYY-MM}   GSI1SK: {login_time}   ← monthly query bucket
  GSI2PK: USER#{sub}              GSI2SK: {login_time}   ← per-user session history
  GSI3PK: STATUS#active|completed|timed_out|revoked   GSI3SK: {last_heartbeat}   ← sweep index

Active Session Pointer (Single Source of Truth per user):
  PK: USER#{sub}
  SK: ACTIVE_SESSION
  Fields:
    sub:            string (Cognito user sub)
    session_id:     string (active session_id)
    device_id:      string (client device UUID passed in /sessions/start)
    status:         "active"
    login_time:     ISO-8601 UTC timestamp
    last_heartbeat: ISO-8601 UTC timestamp
    TTL:            unix epoch

Displacement via TransactWriteItems:
When Device B logs in while Device A is active:
1. Update USER#{sub} / ACTIVE_SESSION to session_id=B, device_id=B (condition: session_id = A).
2. Put SESSION#{B} with status = active (condition: attribute_not_exists(PK)).
3. Update SESSION#{A} with status = completed, end_reason = concurrent_login, logout_time = now (condition: status = active).
All three writes occur in a single atomic TransactWriteItems request so Device A is immediately marked completed with zero delay.

Session ID derivation: sha256(sub + ":" + auth_time)
Chain suffix (#2, #3…) appended when base session has ended, giving each
re-authentication a fresh slot without reopening the closed one.

Item fields:
  session_id:              string (UUID-like sha256 hash, possibly with #N suffix)
  sub:                     string (Cognito user sub)
  device_id:               string | null (client device UUID)
  user_name:               string
  user_email:              string
  user_role:               string
  ip_address:              string
  user_agent:              string
  device_info:             map { browser: string, os: string, device_type: string }
  status:                  "active" | "completed" | "timed_out" | "revoked"
  login_time:              ISO-8601 UTC timestamp
  logout_time:             ISO-8601 UTC timestamp | null
  last_heartbeat:          ISO-8601 UTC timestamp
  duration_seconds:        number (updated on heartbeat and close)
  pages_visited:           list<{ path: string, timestamp: string }> (max 200 entries)
  pages_visited_truncated: boolean
  events_count:            number
  revocation_reason:       string | null
  TTL:                     unix epoch (config aws.dynamodb.log_retention_days, default 90 days)

Stale threshold: 15 minutes (no heartbeat → timed_out)
Sweep command:   sessions:sweep-stale (artisan, scheduled every 10 minutes via console.php)
